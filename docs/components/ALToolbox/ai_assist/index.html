One AI-assisted question: the person answers, AI helps, the person reviews.

An AIAssist object holds the settings and the runtime state for a single assisted answer. The interview itself keeps two ordinary questions: the one that collects the input and the one that shows the suggestion in editable fields. ai_assist.yml supplies everything between them: permission, the call to the AI service, and what happens when the person declines or the service fails.

The object never assigns interview variables. Its suggestions are only defaults on the review screen, so the person's edited answer is what the interview keeps.

AIAssist Objects​

class AIAssist(DAObject)

Settings and state for one AI-assisted answer.

Attributes​

  • task str - One of AI_ASSIST_TASKS. Defaults to "rewrite".
  • source str - Name of the variable that holds the person's input, such as "incident_description". Read when the AI runs.
  • inputs List[str] - Names of more variables to send along with source, for "prompt" and "summarize".
  • instructions str - The prompt for "prompt"; extra instructions for every other task. For "goal" they shape the answer written from the follow-up questions.
  • outputs Dict[str, str] - For "extract" and "extract_file", maps each destination variable name to a description of what to find.
  • choices Dict[str, str] - For "classify", maps each choice value to a description.
  • language str - For "translate", the language to translate into, as an ISO 639 code. Defaults to "en".
  • rubric str - For "goal", what a complete answer includes.
  • initial_question str - For "goal", the question the person answered.
  • question_limit int - For "goal", the most follow-up questions to ask. Defaults to 3.
  • model str - A model to use instead of the server's default.
  • ask_permission bool - Ask before sending anything to the AI service. Defaults to True.
  • purpose str - Finishes "AI can ..." on the permission screen.
  • use_ai bool - The person's answer on the permission screen.
  • status str - "suggested", "declined", "unavailable" or "error" after run().

Example​

include:
  - docassemble.ALToolbox:ai_assist.yml
---
objects:
  - incident_ai: AIAssist.using(task="rewrite", source="incident_description")
---
question: Review your description
subquestion: ${ incident_ai.review_note() }
fields:
  - no label: incident_narrative
    datatype: area
    default: ${ incident_ai.suggestion() }

run​

def run() -> Any

Call the AI service once for the current input and settings.

Gets the person's input, then asks for use_ai: the permission screen says the answer will be sent, so it has to follow the answer. Returns the raw, unvalidated result, or None when the person declined, no service is configured, or the call failed. Remembers the result, so showing the review screen again, going back, or resuming the session doesn't repeat the call. Changing the input or the settings does.

retry​

def retry() -> None

Forget the last result, so the next run() calls the AI again.

For "goal", a follow-up question that failed is tried again; the answers already given are kept.

suggestion​

def suggestion(name: Optional[str] = None) -> Any

The suggested value to show on the review screen.

Without name, the suggested text (or choice) for a one-answer task. With name, the suggested value for that destination variable of an extraction. Falls back to the person's own input for text tasks and to an empty value otherwise, so the review screen always works.

AIAssistFollowUps Objects​

class AIAssistFollowUps(llms.GoalOrientedQuestionList)

The follow-up questions of an AIAssist with task "goal".

The list's own code blocks call the AI service while docassemble gathers it, outside any code in AIAssist. Here a failed call ends the follow-up questions instead of the interview: ai_failed is set and the person goes on to review what they have said so far.
